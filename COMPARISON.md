# Playwright или Cypress: плюсы, минусы, рекомендация

Сравнение сделано на демо-магазине Lumen Store (React + Django + Postgres + WebSocket). В обоих фреймворках один и тот же набор пользовательских сценариев (UC-01…UC-15, см. `REPORT.md`).

## Результаты на Docker-стеке

| | Playwright | Cypress |
|---|---|---|
| Сценариев | 15 | 14 (UC-15 в Cypress не реализуем) |
| Результат | 15/15 | 14/14 |
| Время прогона | 34,8 с | 22 с |

Playwright сейчас запускается в один поток (`workers: 1`): все авторизованные сценарии работают под одним тестовым аккаунтом с общей корзиной.

## Playwright

### Плюсы

- **Видно, почему тест упал на проде.** Trace Viewer записывает каждый шаг: снимок страницы, сетевые запросы, консоль и видео. Тест упал ночью в CI — открываешь трейс и видишь, что там было. Для прогонов на проде это главное.
- **Параллельный запуск бесплатно и из коробки.** С несколькими тестовыми аккаунтами прогон ускорится в разы.
- **Умеет больше:** проверять содержимое сообщений вебсокета (UC-15), открывать несколько вкладок и пользователей в одном тесте, работать с iframe и скачиванием файлов.
- **Все браузеры, включая Safari (WebKit).**
- **Обычный `async/await`:** код читается как обычный JS, переменные работают как обычно.
- **Встроенный HTML-отчёт**, плагины не нужны.

### Минусы

- **Браузеры надо ставить отдельно** (`npx playwright install`) или использовать системный Chrome через `channel: 'chrome'` в конфиге.
- **Проверка видимости мягче.** Баг с «уезжающей» шапкой Playwright пропустил, а Cypress поймал.
- **Встречаются подвохи с окружением.** Например, версия 1.49 молча зависала на Node 24 при `"type": "module"` в `package.json`.
- **В нашем замере медленнее** (35 с против 22 с), потому что тесты идут в один поток.

## Cypress

### Плюсы

- **Самый наглядный интерактивный режим:** видно, как тест «живёт» в браузере, и можно отмотать к любому шагу (time-travel). Новичку проще начать.
- **Строже проверяет видимость.** Именно Cypress поймал реальный баг вёрстки: `overflow-x: hidden` ломал `position: sticky` у шапки.
- **В последовательном прогоне быстрее.**
- **Большое сообщество** и много готовых примеров.

### Минусы

- **Параллельный запуск — через платный Cypress Cloud.**
- **Нет доступа к сообщениям вебсокета**: проверить можно только косвенно, через интерфейс.
- **Только одна вкладка**: сценарии с несколькими пользователями одновременно не сделать.
- **Нет Safari (WebKit).**
- **Своя модель команд:** нельзя просто написать `const x = await ...`, нужны `.then` и алиасы. Есть подвохи: например, без `{ type: 'static' }` алиас при каждом обращении заново ищет элемент на странице.
- **Для HTML-отчёта нужен плагин** (здесь `cypress-mochawesome-reporter`).
- **Тяжёлый бинарник** (~500 МБ). В этом проекте npm 11 заблокировал его автоматическую установку, пришлось ставить вручную через `npx cypress install`.

## Сводная таблица

| Критерий | Playwright | Cypress |
|---|---|---|
| Разбор падений в CI | ✅ Trace Viewer: DOM, сеть, консоль, видео | ⚠️ скриншоты, видео |
| Интерактивный режим | ✅ UI mode | ✅✅ time-travel, самый наглядный |
| Параллельный запуск | ✅ бесплатно | ❌ через платный Cloud |
| WebSocket | ✅ прямой доступ к сообщениям | ❌ только через UI |
| Несколько вкладок или пользователей | ✅ | ❌ |
| Safari (WebKit) | ✅ | ❌ |
| Строгость проверки видимости | ⚠️ мягче | ✅ строже |
| Порог входа | ✅ обычный JS | ⚠️ своя модель команд |
| Отчёты | ✅ встроенные | ⚠️ нужен плагин |
| Установка | ⚠️ браузеры отдельно | ⚠️ тяжёлый бинарник |

## Рекомендация: Playwright

Задача — тестировщик сам запускает основные пользовательские сценарии на проде, когда удобно. Для неё лучше подходит **Playwright**:

1. **Разбор падений.** На проде нельзя воспроизвести падение руками в любой момент. Трейс Playwright сразу показывает, что произошло, и в CI это особенно ценно.
2. **Масштаб.** Сценариев со временем станет больше. Playwright распараллеливается бесплатно, в Cypress за это придётся платить.
3. **Возможности приложения.** В приложении есть вебсокеты. Playwright проверяет их напрямую, Cypress — только косвенно, через интерфейс.
4. **Сценарии с несколькими пользователями** (например, «покупатель оформил — админ увидел») в Cypress не делаются.

**Когда выбрать Cypress:** если для команды важнее всего порог входа и наглядный интерактивный режим, а тестов немного и они идут в одном браузере.

**Как закрыть сильную сторону Cypress в Playwright:** добавить скриншотное сравнение `toHaveScreenshot()` для ключевых страниц. Оно ловит поломки вёрстки (как баг с шапкой) даже надёжнее.

## Что сделать после выбора Playwright

- Перевести конфиг на системный Chrome (`channel: 'chrome'`), чтобы не скачивать браузер.
- Завести несколько тестовых аккаунтов (по одному на поток) и включить параллельный запуск.
- Добавить `toHaveScreenshot()` для каталога, корзины и оформления заказа.
- Включить ежедневный прогон по расписанию в `.github/workflows/e2e-prod.yml`.
