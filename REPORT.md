# Отчёт: демо-магазин Lumen Store и сравнение Playwright и Cypress

## Итог

- Тесты бэкенда (API и WebSocket): **21/21**
- Playwright: **15/15** (~26 с)
- Cypress: **14/14** (~19 с)

Всё проверено на Docker-стеке (`docker compose up --build`: Postgres, Redis, nginx). Тесты бэкенда запускались внутри контейнера, e2e — против http://localhost:8080. Время прогона в Docker: Playwright 34,8 с, Cypress 22 с.

## Структура проекта

| Папка/файл | Что внутри |
|---|---|
| `frontend/` | React 18 + Vite: каталог, корзина, покупка, «Мои заказы», колокольчик с уведомлениями. Тёмная тема, градиенты, анимации |
| `backend/` | Django 5 + DRF + Channels, Postgres, Redis для вебсокетов. В базе товары, пользователи, их корзины (выбранные товары) и заказы (купленные). Заполняется при старте контейнера |
| `e2e/` | одни и те же сценарии на Playwright (`e2e/playwright/`) и Cypress (`e2e/cypress/`) |
| `docker-compose.yml` | база, Redis, бэкенд, фронтенд (nginx) |
| `.github/workflows/e2e-prod.yml` | запуск тестов на проде по кнопке из GitHub Actions |

## Два сценария

- **Гость.** Смотрит каталог, ищет и фильтрует товары, кладёт их в корзину. Купить не может: кнопка оформления заблокирована, а переход на `/checkout` ведёт на страницу входа.
- **Авторизованный пользователь.** Покупает, видит историю заказов. При входе гостевая корзина переносится в аккаунт.

## WebSocket-уведомления

- Адрес: `ws://<host>/ws/notifications/?token=<api-token>`.
- Гость получает общие рассылки, авторизованный пользователь — ещё и личные уведомления о своих заказах.
- После оплаты приходит уведомление, и статус заказа сам меняется «Оплачен → Собирается → Передан в доставку» без перезагрузки страницы. Пауза между статусами задаётся через `ORDER_STATUS_DELAY` (по умолчанию 3 с).
- Тесты есть на трёх уровнях: тесты бэкенда и сценарии UC-11…UC-15 в обоих фреймворках.
- UC-15 есть только в Playwright: он проверяет содержимое сообщений вебсокета, а у Cypress такой встроенной возможности нет.

## Как тестировщику запускать на проде

Подготовка (один раз):

```bash
cd e2e
npm install
npx playwright install chromium
```

**Локально:**

```bash
cd e2e
BASE_URL=https://прод TEST_USER_EMAIL=... TEST_USER_PASSWORD=... npm run pw   # или npm run cy
```

| Задача | Playwright | Cypress |
|---|---|---|
| Прогон в консоли | `npm run pw` | `npm run cy` |
| Интерактивный режим | `npm run pw:ui` | `npm run cy:ui` |
| Интерактивный режим в браузере | `npm run pw:ui:web` → http://localhost:9323 | `npm run cy:ui:web` → сразу открывается Chrome |
| С видимым браузером | `npm run pw:headed` | `npm run cy:headed` |
| HTML-отчёт | `npm run pw:report` | `npm run cy:report` |

**По кнопке из GitHub:** Actions → «E2E на проде» → Run workflow, там выбирается фреймворк (`both` / `playwright` / `cypress`). HTML-отчёты прикрепляются к прогону. Для этого в репозитории нужно один раз завести:
- переменную `PROD_URL`;
- секреты `TEST_USER_EMAIL` и `TEST_USER_PASSWORD`.

В workflow есть закомментированный `schedule` для ежедневного прогона.

**Важно для прода:** тесты готовят данные только через API — перед каждым сценарием очищают корзину тестового аккаунта. Но каждый прогон создаёт на проде несколько заказов (UC-09, UC-13, UC-14, UC-15). Поэтому для реального прода нужен отдельный тестовый аккаунт и тестовый режим оплаты.

## Сравнение Playwright и Cypress

| | Playwright | Cypress |
|---|---|---|
| Результат на демо | 15/15 | 14/14 |
| Время прогона (локально) | ~26 с | ~19 с |
| Стиль кода | `async/await`, обычный JS | цепочки команд, свои правила для переменных (`.then`, алиасы) |
| Подготовка данных через API | `request` | `cy.request` |
| Содержимое WebSocket-сообщений | есть из коробки | нет, только плагины или обходные пути |
| Несколько вкладок в одном тесте | есть | нет |
| Браузеры | Chromium, Firefox, WebKit (Safari) | Chrome, Edge, Firefox, Electron; без Safari |
| Отладка | Trace Viewer: DOM, сеть и консоль на каждом шаге, видео | time-travel в интерактивном раннере, скриншоты |
| Отчёт | встроенный HTML | нужен плагин (`cypress-mochawesome-reporter`) |
| Параллельный запуск | встроенный, бесплатный | через платный Cypress Cloud |

### Что выяснилось по ходу работы

- **Cypress нашёл настоящий баг вёрстки:** шапка не залипала при прокрутке (`overflow-x: hidden` на корневом контейнере ломал `position: sticky`). Playwright его пропустил. Баг исправлен (`overflow-x: clip`).
- **Подвох Cypress:** запомненное через `.as()` значение по умолчанию заново ищется на странице при каждом обращении. Чтобы сохранить его, нужен `{ type: 'static' }`.
- **Подвох Playwright:** версия 1.49 на Node 24 молча зависает, если в `package.json` указан `"type": "module"`. Поэтому в `e2e/package.json` его нет.
- **В пользу Playwright:** проверка содержимого вебсокетов, несколько вкладок в одном тесте, Safari (WebKit), встроенные отчёт и параллельный запуск.
- **Скорость:** сейчас Playwright идёт в один поток, потому что все сценарии работают под одним тестовым аккаунтом. Если завести по аккаунту на поток, его можно распараллелить, и он станет быстрее Cypress.
